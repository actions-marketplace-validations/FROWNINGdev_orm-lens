# DOL007 — 可能的 N+1：在 for 循环中访问属性

**默认严重程度：** warning · **适用性：** unsafe · **类别：** queryset

检测 `for x in <queryset>:` 之后在循环体中访问 `x.<attr>` 的写法（只检查循环体的前 15 行；忽略 `id`、`pk`、`save` 以及以下划线开头的属性；每个循环最多报告一次）。如果 `<attr>` 是 `ForeignKey` / `OneToOneField`，每次迭代都会触发一次单独的查询——这就是典型的 N+1：循环本身一次查询，外加每行一次。`select_related()`（SQL 连接）或 `prefetch_related()`（批量执行的第二次查询）可以把查询次数降为常数。

本规则仍为 `unsafe`，并且不提供 QuickFix：修复方式取决于对 queryset 用法的判断，而不是机械式的编辑。

## 两道关卡，避免在没有开销的代码上报告

在 0.18.0 之前，本规则只看代码行的形状，因此会在普通列、继承来的 Python 属性上触发，甚至会在同一语句已经跨越的外键上触发——见 [#85](https://github.com/FROWNINGdev/orm-lens/issues/85)。现在的两道关卡与 CLI 的 [`nplusone` 分析器](../../../rules/nplusone.md)一贯的做法一致，并且有意设计为相互独立。

**标量（需要工作区索引）。** 模式（schema）中声明为非关系字段的属性会被跳过。*已知*模型根本没有声明的属性同样会被跳过——从外部看，抽象基类上的 `@property` 就是这个样子，而在这里猜测其为“关系”，正是大多数误报的来源。在第一次工作区扫描完成之前，这道关卡不会生效，因此冷启动时的行为与以前相同，而不会依据尚未获得的模式给出看似确定的报告。

**已覆盖（无需任何前提）。** 如果某个关系已经在生成该循环的调用链上的 `.select_related(...)` 或 `.prefetch_related(...)` 中指明，就会被跳过；不带参数的 `.select_related()` 也包括在内，因为它会跨越所有外键。这完全是字符串匹配，因此在冷启动时同样有效——正是这道关卡，避免本规则与已经采纳其建议的代码相矛盾。

查找调用链时，不仅看循环头，也看变量的绑定处：最多向上查找 40 行，并且跨越续行，因为先写 `codes = list(OneTimeCode.objects.select_related("issued_by"))`、再写 `for code in codes:`，是很常见的写法。遇到 `def`/`class` 边界或无法识别的绑定时，查找就会停止，而不会继续追溯到同名变量更早的绑定。

索引中不存在的模型*不会*被视为“标量”——本规则在这种情况下会回退到 0.18 之前的行为，因此不完整的扫描不会掩盖真正的问题。

## 哪些循环在检查范围内

循环头按文本读取，并且只根据可迭代对象本身作出判断。

不含 `(` 的可迭代对象——单独的名称（`for user in users:`）或点号连接的属性链（`for entry in self.pending:`）——在检查范围内。它没有指明任何调用，因此单独一行代码无法说明它是或不是 queryset，而 `users = User.objects.all()` 又是常见的写法。出于同样的原因，绑定到列表的名称也在检查范围内，所以 `k_entries = ["a", "b"]` 之后跟着 `for e in k_entries: print(e.upper)` 会被报告。

含有 `(` 的可迭代对象，只有在第一个 `(` 之前的文本恰好是中间一段为 `objects` 的三段点号路径（`<Model>.objects.<method>`），或者是最后一段为生成 queryset 的方法的点号链（`all`、`filter`、`exclude`、`annotate`、`distinct`、`order_by`、`values`、`values_list`、`reverse`、`none`、`iterator`、`only`、`defer`、`using`、`alias`、`dates`、`datetimes`、`union`、`intersection`、`difference`、`select_related`、`prefetch_related`、`extra`、`select_for_update`、`raw`）时，才在检查范围内。

其他所有形如调用的来源都会被跳过：`range(10)`、`os.listdir(path)`、`apps.get_models()`，以及 `auditory_models()` 或 `self.get_queryset()` 这样的辅助函数调用。仅凭调用名称无法判断返回的是什么，要弄清楚就必须追踪被调用函数的返回值，而这需要 AST，本规则这种逐行检查并不具备。代价是漏报——确实返回 queryset 的辅助函数也会被跳过。

## 错误示例

```python
for post in Post.objects.all():
    print(post.author.name)   # one extra query per post
```

## 正确示例

```python
for post in Post.objects.select_related("author"):
    print(post.author.name)   # single joined query
```

## 禁用规则

```python
# orm-lens-disable-next-line DOL007
```
